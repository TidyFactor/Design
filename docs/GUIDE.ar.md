## 1. النموذج الذهني: هندسة التصميم مقابل التخمين العشوائي بالبرومبت

التعامل التقليدي مع الذكاء الاصطناعي يعامل تصميم الواجهات كبرومبت عشوائي:
```
المستخدم: "صمم لي صفحة هبوط لبرنامج CRM"
النموذج: يخرج ملف HTML عشوائي بتنسيقات داخلية (Inline styles)، وألوان غير موحدة، ومكونات مكررة وهشة.
```

بينما تحول **TidyFactor Design** الأمر إلى **نظام تشغيل هندسي**:
```
┌───────────────────────────────────────────────────────────┐
│                     معرفة التصميم الموثقة                 │
│      الذاكرة التشغيلية (المصفوفات) + سير العمليات المنظم  │
└─────────────────────────────┬─────────────────────────────┘
                              ▼
┌───────────────────────────────────────────────────────────┐
│                     وكيل البرمجة الذكي                    │
│      يبني design-system/ مع انعدام تام للـ Inline CSS     │
└─────────────────────────────┬─────────────────────────────┘
                              ▼
┌───────────────────────────────────────────────────────────┐
│                      الفحص الآلي الحتمي                   │
│        ختم المحاور الـ 7 + فحص كشف الهلوسة البرمجية       │
└───────────────────────────────────────────────────────────┘
```

### القواعد المعمارية الجوهرية:
1. **انعدام تام للـ CSS/JS الخاص بكل صفحة (Zero per-page CSS/JS)**: توضع كافة متغيرات التصميم والمكونات داخل مجلد `design-system/`. تحتوي الصفحات داخل `pages/` على وسوم HTML دلالية نظيفة فقط.
2. **قفل الأساس البرمجي (Single CSS Foundation)**: اختر الأساس (Native CSS, Tailwind, daisyUI, shadcn/ui, Pico, Hybrid) مرة واحدة أثناء أمر `/init`. يُمنع الخلط بين الأسس في المشروع الواحد.
3. **أولوية الذاكرة التشغيلية**: ملفات الذاكرة في `references/memory/` هي قيود وقواعد هندسية خالصة بدون حشو تسويقي.

## 2. استكشاف الوكلاء وإعداد بيئة العمل

### تثبيت المهارة
```bash
# عبر سطر أوامر تايدي فاكتور (NPM)
npx @tidyfactor/cli add tidyfactor-design

# عبر معيار skills.sh المفتوح
npx skills add TidyFactor/Design
```

### الوكلاء المدعومون
- **Google Antigravity**: اكتشاف تلقائي داخل `.agents/skills/tidyfactor-design` أو المسار العام للمستخدم.
- **Claude Code**: تشغيل مباشر للأوامر السريعة `/brief` و `/init` و `/components`.
- **Cursor / Codex / Windsurf**: توجيه سياقي سلس من ملف `SKILL.md`.

## 3. دليل تطبيقي متسلسل: بناء نموذج تفاعلي متكامل عبر المراحل السبع

### المرحلة 1: الاستكشاف الاستراتيجي (`/brief`)
قبل البدء في كتابة أي كود، استدعِ طبقة القرار السياقي لحل المجهولات:
```bash
/brief
```
يقوم الوكيل بمسح بيئة العمل وملفات المشروع القائمة تلقائياً، ولا يسأل المستخدم إلا عن المجهولات الحقيقية:
- **نمط الجمهور (Audience Mode)**: إلهام (Inspire)، تقييم (Evaluate)، تحفيز للإجراء (Act)، أو تعلم (Learn).
- **نوع الواجهة (Surface Type)**: هبوط (Landing)، لوحة تحكم (Dashboard)، منتج، أو مقالات.
- **المدرسة الجمالية (Tone School)**: سويسرية، نيو بروتاليزم، فاخرة، بينتو، أو تراثية.

*المخرج*: قفل المعطيات في `.tidyfactor/design-brief.snapshot.json` و `design-brief.md`.

### المرحلة 2: بناء الأساس البرمجي (`/init` و `/brand`)
بناء هيكل المشروع بدون خطوات تجميع معقدة:
```bash
/init --foundation native --school swiss-international
```
ينتج عن هذا الهيكل التالي:
```
project-root/
├── brand.yaml                    # الحقيقة الموحدة لرموز العلامة والتصميم
├── brand.json                    # مرآة للتوافق العكسي
├── design-system/
│   ├── tokens.css                # متغيرات CSS القياسية (ألوان، خطوط، هوامش)
│   ├── components.css            # فئات المكونات التفاعلية بحالاتها الثماني
│   └── motion.js                 # وصفات الحركة والربط مع GSAP
├── pages/                        # صفحات المحتوى الدلالية النظيفة
└── index.html                    # المدخل الرئيسي
```

### المرحلة 3: الخطوط ولوحة الألوان (`/typography` و `/palette`)
استخراج ألوان معتمدة لمعايير التباين WCAG 2.1 AAA من شعار العلامة:
```bash
python scripts/extract_palette.py assets/logo.png --yaml
```
اختيار اقتران الخطوط المناسب:
```bash
/typography --mood confident-saas
```
- **العناوين العربية**: El Messiri (المصيري)
- **النصوص العربية**: Tajawal (تجوال)
- **العناوين اللاتينية**: Outfit أو Plus Jakarta Sans
- **النصوص اللاتينية**: Inter أو Roboto

### المرحلة 4: الهيكل والتوزيع المعماري (`/layout` و `/nav-footer`)
تركيب حاويات الشبكة L1–L4:
```bash
/layout --archetype L1-split-hero
/nav-footer --nav N3-floating-glass --footer Ft2-minimal-split
```

### المرحلة 5: تركيب المكونات (`/components`)
بناء المكونات استناداً إلى المصفوفات المعتمدة:
- إضافة شارات الترويسة (`21-eyebrow-kicker-matrix.md`)
- إضافة قسم هيرو ديناميكي (`22-hero-section-matrix.md`)
- إضافة بطاقات متجاوبة بتثبيت الأزرار في الأسفل (`23-card-architecture-matrix.md`)
- إضافة أزرار بحالاتها الثماني (`24-button-cta-matrix.md`)

### المرحلة 6: الفحص وضمان الجودة الميكانيكي (`/audit`)
تشغيل الفاحص البرمجي الحتمي للتأكد من انعدام الـ Inline Styles ومطابقة الجودة:
```bash
/audit
# أو تشغيل السكربت الحتمي مباشرة:
python scripts/audit_design.py --target .
```
التحقق من وجود الختم:
```css
/* Pre-emit critique: P5 H5 E5 S5 R5 V5 D5 */
```

### المرحلة 7: تسليم الكود للمطورين (`/handoff`)
استخراج جداول التسليم الدقيقة الجاهزة للدمج في React أو Next.js أو PHP:
```bash
/handoff --framework react-tailwind
```

## 4. كتالوج مصفوفات المكونات والفواصل (المجلدات 01–03)

### شارات الترويسة (Volume 01)
```html
<div class="c-eyebrow c-eyebrow--pill" data-accent="emerald">
  <span class="c-eyebrow__dot"></span>
  <span class="c-eyebrow__label">الإصدار v1.9.0 متاح الآن</span>
</div>
```

### فواصل الأقسام البارامترية (Volume 03)
ينتمي الفاصل للقسم السابق ويستمد لونه ديناميكياً من القسم اللاحق:
```html
<section class="s-hero s-hero--light">
  <!-- محتوى القسم -->
  <div class="c-seam c-seam--wave" aria-hidden="true">
    <svg viewBox="0 0 1440 80" preserveAspectRatio="none">
      <path d="M0,0 C360,60 1080,60 1440,0 L1440,80 L0,80 Z" fill="var(--color-surface-next)" />
    </svg>
  </div>
</section>
```

### شرط استقامة الأزرار في البطاقات
إلزامية استخدام `display: flex; flex-direction: column;` مع `margin-top: auto` لمنع تفاوت مستويات الأزرار:
```css
.c-card {
  display: flex;
  flex-direction: column;
}
.c-card__footer {
  margin-top: auto;
}
```

## 5. معايير مناهضة التكرار (Anti-Slop) وبوابات الجودة الحتمية

ترفض المهارة أنماط الذكاء الاصطناعي المكررة آلياً:
1. **منع هيرو التدرج البنفسجي المبتذل**: حظر دمج `#7C3AED` مع `#EC4899` كنص أبيض بالوسط.
2. **منع الأسود والأبيض الصريحين**: استخدام درجات رمادية محايدة مدروسة (`#0F172A`).
3. **محاذاة الأزرار الأفقية**: إلزامية محاذاة أزرار البطاقات عبر `mt-auto`.
4. **منع إخفاء زر الإجراء**: التأكد من أن الهيرو لا يدفع زر الإجراء الرئيسي تحت خط الرؤية (Below the Fold).
5. **حظر شبكات الخطوط العشوائية**: منع وضع خلفيات الشبكات الهندسية في المواقع غير التقنية.

## 7. هندسة الواجهات العربية وثنائية اللغة (RTL/LTR)

- **العناوين**: استخدام خط `El Messiri` (`font-family: var(--font-arabic-heading)`).
- **المتن**: استخدام خط `Tajawal` (`font-family: var(--font-arabic-body)`).
- **قاعدة صارمة**: حظر استخدام خط `Amiri` للعناوين بحجم يتجاوز 24px (خط كتابي نسخ لا يصلح للعناوين الضخمة).
- **الانعكاس المنطقي**: استخدام الخصائص المنطقية الحديثة في CSS (`margin-inline-start`, `padding-inline-end`) بدلاً من `left` و `right`.
